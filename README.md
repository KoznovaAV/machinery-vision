Экспериментальный MVP распознавания сельхозтехники: **тип → семейство → кандидаты точной модели**, выделение нескольких машин, OCR маркировки и оценка видимого состояния. Если признаков недостаточно, система сообщает о неопределённости.

**Текущий выпуск: `maintenance_round6`, 16 ноября 2026 года.** [Передача разработчику](docs/HANDOVER.md) · [Состояние проекта](docs/CURRENT.md) · [Отчёт выпуска](reports/MAINTENANCE_ROUND6_2026-11-16.md).

## Возможности и границы классов

- Выделение объектов: Grounding DINO; признаки: DINOv2 Small + ConvNeXt Tiny; отдельные классификаторы, пороги, проверка областей и OCR.
- Восемь семейств-кандидатов: МТЗ-80/82/820, МТЗ-1221, МТЗ-1523, New Holland T5000, CLAAS AXION 800, ДТ-75, Т-150К, ACROS. Есть также отказ/неизвестный класс.
- Пороги принятого ответа настроены для пяти семейств: МТЗ-80/82/820, МТЗ-1221, T5000, AXION 800 и ДТ-75. ACROS, МТЗ-1523 и Т-150К пока показываются кандидатами.
- Специалист МТЗ и анализ переднего моста помогают оценить варианты 80/82/820. **Точная модификация автоматически не подтверждается.** T5000 и AXION 800 — серии, а не точные модели.
- Прицепы/цистерны проходят отдельную проверку. Неоднозначные области показываются человеку без уверенного назначения модели и состояния.
- Грязь оценивается с возможностью отказа. Снег в сцене не равнозначен снегу на машине; дождь и мокрый корпус пока недостаточно проверены.

Состав классов и смысл меток: [справочник](configs/machinery_taxonomy.json). Типы, отсутствующие в обучении, не считаются поддержанными только потому, что их нашёл детектор.

## Запуск в существующей рабочей копии на D

Windows PowerShell, Python 3.11. Команды используют уже подготовленное окружение и веса; установка зависимостей не нужна.

```powershell
Set-Location 'D:/machinery-vision/project'
$python = 'D:/machinery-vision/envs/tractor/Scripts/python.exe'
New-Item -ItemType Directory -Force 'output/tmp' | Out-Null
$env:PYTHONUTF8 = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:TEMP = "$PWD/output/tmp"
$env:TMP = $env:TEMP
$env:TORCH_HOME = 'D:/machinery-vision/envs/torch-cache'
$env:HF_HOME = "$PWD/weights/hf-cache"
$env:HF_HUB_OFFLINE = '1'
$env:TRANSFORMERS_OFFLINE = '1'
$env:NO_ALBUMENTATIONS_UPDATE = '1'
$env:MPLCONFIGDIR = 'D:/machinery-vision/envs/matplotlib-cache'
$env:YOLO_CONFIG_DIR = 'D:/machinery-vision/envs/ultralytics-config'
& $python -B -m scripts.check_mvp_release
& $python -B -m scripts.serve_hierarchy_review --port 7864
```

Открыть **<http://127.0.0.1:7864/>**. Загрузить JPEG/PNG/WebP до 8 МБ, размером не меньше 64 пикселей по каждой стороне. Остановка сервера — `Ctrl+C`. Если интерфейс уже запущен на этом порту, второй экземпляр не нужен. Первая обработка загружает модели и может занять заметное время.

Результаты и загруженные фото сохраняются локально в `output/hierarchy_review/`. Сервер слушает только `127.0.0.1`; это интерфейс проверки человеком, `/predict` возвращает HTML.

## Установка из GitHub на новом рабочем месте

Нужны Git, Python 3.11, свободное место на D и интернет для первоначальной установки. Пример для ещё не существующей папки `D:/machinery-vision/project`:

```powershell
New-Item -ItemType Directory -Force 'D:/machinery-vision' | Out-Null
Set-Location 'D:/machinery-vision'
git clone https://github.com/KoznovaAV/machinery-vision.git project
Set-Location 'project'
New-Item -ItemType Directory -Force 'output/tmp' | Out-Null
$env:TEMP = "$PWD/output/tmp"
$env:TMP = $env:TEMP
$env:PYTHONUTF8 = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:NO_ALBUMENTATIONS_UPDATE = '1'
$env:TORCH_HOME = "$PWD/weights/torch-cache"
$env:HF_HOME = "$PWD/weights/hf-cache"
$env:MPLCONFIGDIR = "$PWD/output/matplotlib-cache"
$env:YOLO_CONFIG_DIR = "$PWD/output/ultralytics-config"
py -3.11 -m venv .venv
$python = "$PWD/.venv/Scripts/python.exe"
& $python -m pip --no-cache-dir install torch torchvision --index-url https://download.pytorch.org/whl/cpu
& $python -m pip --no-cache-dir install -r requirements-hierarchy.txt
& $python -B -m scripts.setup_hierarchy_weights
& $python -B -m scripts.check_mvp_release
& $python -B -m scripts.serve_hierarchy_review --port 7864
```

Базовые веса DINOv2, Grounding DINO и ConvNeXt занимают около 0,9 ГБ и загружаются из открытых источников с проверкой SHA-256. В Git уже включены головы, пороги и эталоны текущего MVP. Фотографии для запуска собственного распознавания не нужны: загрузите своё фото через интерфейс. [Подробности подготовки весов](docs/HIERARCHY_WEB.md).

Проверенное окружение Windows: Python 3.11.15; версии основных библиотек сохранены в [runtime_versions.json](reports/maintenance_round6/runtime_versions.json). Файлы requirements не являются полным lock-файлом; новая установка может получить другие версии и требует проверки. Для полностью автономного переноса нужно также передать базовые веса/кэш и совместимое окружение.

## Проверки и результаты

После настройки переменных окружения из команд выше:

```powershell
& $python -B -m scripts.check_mvp_release
& $python -B -m pytest tests -q -p no:cacheprovider --basetemp "$PWD/output/pytest-tmp"
```

Проверка SHA подтверждает согласованность кода и артефактов, **не точность распознавания**. В комплекте без локальных данных проверены 213 тестов, 9 пропущены из-за отсутствия реальных данных/чекпоинта старого API; тесты текущего MVP используют заглушки или компактные артефакты и не требуют больших энкодеров. Полные фото-прогоны дополнительно требуют локальные контрольные фотографии и файлы рабочих запусков.

Последние две строки относятся к сохранённым признакам и правилам отдельных голов, а не к повторной полной оценке приложения после изменения выделения областей. Показатели нового полного конвейера на всех 158 фото не заявляются.

Новые головы грязи и снега обучены, но **не установлены**: грязь дала 25 ответов без ошибок вместо прежних 39 ответов с одной ошибкой на 63 размеченных оценках; снег — 7 вместо 8 ответов на 81 оценке. Прежние веса состояния сохранены, добавлен отказ при спорной поверхности. Нулевые ошибки при отсутствии ответов не считаются улучшением.

## Ограничения

- Это экспериментальный MVP; ошибки семейств, пропуски объектов и ложные области ещё возможны. Ночь, частичное перекрытие, грязь и зимние сцены остаются сложными.
- Прежний контроль многократно использовался при диагностике. Он не является слепым итоговым тестом. Нет гарантии отсутствия регрессий на новых фото.
- Новые визуальные разметки выполнены ассистентом и не прошли предметную приёмку специалистом. Часть контрольных групп состояния пересекается с обучением распознавания; независимость всего конвейера ограничена.
- Недостаточно независимых положительных примеров дождя/мокрой поверхности. Снег на фоне не доказывает заснеженность техники. Отказ «состояние не удалось оценить» допустим.
- Мобильная интеграция, публичный JSON API текущего конвейера, проверка нагрузки и перенос на устройство не выполнены.
- Самообучение и автоматическая замена модели не включены. Собственные прогнозы и исправления пользователей требуют проверки перед обучением.

## Данные, состав выпуска и передача

| Что | Где |
|---|---|
| Активный выпуск, SHA кода и артефактов | `artifacts/mvp/current_release.json`, `maintenance_round6_release.json` |
| Головы, пороги, эталоны | `artifacts/mvp/` — включены в Git |
| Детектор и большие энкодеры | `weights/`, кэш `TORCH_HOME` — скачиваются отдельно |
| Фото и рабочие манифесты обучения/контроля | Локальные `data/` и `output/` — не включены в Git |
| Последнее обучение/сравнение | `output/maintenance_round6/` локально; компактные отчёты — `reports/maintenance_round6/` |
| Предыдущий комплект | Локально `output/maintenance_round6/baseline/`; старые эталоны также сохранены в `artifacts/mvp/` |

Для повторного обучения передать фотографии **вместе** с манифестами, контрольными суммами и группами из рабочей копии. В частности, текущий манифест — `output/trailer_round5/dataset_manifest.json`; новые области и источники описаны в опубликованных отчётах. JSON без изображений недостаточен. Права на распространение собранных фото не подтверждены: публикация фото в открытом репозитории не выполняется.

Для отката сохранять вместе Git-коммит, справочник, все головы, пороги и эталоны. После переключения версии запускать проверку целостности и фото-прогон; не смешивать файлы разных выпусков. До первого отката отдельно сохранить полный комплект текущего выпуска.

Следующему разработчику: принять разметку со специалистом, собрать новый контроль от других владельцев/съёмок, доработать экземплярную разметку и состояние, затем обучать кандидата и сравнивать по прежним классам, погоде, отказам и ошибочным уверенным ответам. Порядок сопровождения и передачи — в [HANDOVER.md](docs/HANDOVER.md).

## Старый API и история

В `src/api/`, части `src/training/`, Docker/Gradio и документах `ARCHITECTURE.md`, `DATA.md`, `RETRAIN.md` сохранён **старый API v3 с четырьмя семействами**. Его метрики и контур обратной связи не описывают текущий MVP. `uvicorn src.api.main:app` и Docker Compose запускают старый конвейер; для демонстрации текущего выпуска используйте команды выше.

`artifacts/hierarchy/` и прежние отчёты — исторические снимки. Актуальный комплект выбирается по `artifacts/mvp/current_release.json`. Копирование новых файлов в `artifacts/hierarchy/` не обновляет текущую модель.
