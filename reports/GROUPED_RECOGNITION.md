# Проверка распознавания на группах снимков

Продолжение [аудита данных](DATASET_AUDIT_2026-11-14.md). Эксперименты проведены
локально на CPU. Манифесты, коэффициенты линейной головы и JSON с результатами
лежат в `output/dataset_audit_next/`.

В наборе из 703 исходных кадров три вероятных игровых рендера помечены для
исключения. Остальные кадры распределены в пропорции 420/140/140.
Манифест содержит SHA‑256, исходный и новый сплиты, идентификатор группы
и флаги просмотра. Группы учитывают точные совпадения, pHash с расстоянием
до 8, зеркальные версии и несколько вручную отмеченных серий. Между сплитами
общих групп нет. Две группы включают несколько семейств из-за похожих
силуэтов и фона. Это консервативная группировка, которую можно уточнить
после подтверждения реального экземпляра машины и источника. Статистики
на новом сплите относятся к отдельно обученным головам. Текущая v3
обучалась на других сплитах, содержавших часть новых тестовых кадров.

| Бэкбон и вход 224 px | Семейство, val | Семейство, test | МТЗ, групповые фолды | Macro-F1 МТЗ | Внешние кадры МТЗ |
|---|---:|---:|---:|---:|---:|
| ConvNeXt-Tiny, центральный кроп | 137/140 | 137/140 | 70/89 | 0,759 | 3/4 |
| EfficientNet-B0, центральный кроп | 135/140 | 139/140 | 75/89 | 0,814 | 1/4 |
| DINOv2 Small, центральный кроп | 139/140 | 139/140 | 79/89 | 0,872 | 4/4 |
| DINOv2 Small, вписывание кадра | 136/140 | 140/140 | 82/89 | 0,911 | 4/4 |

Для МТЗ использовались те же 89 кадров с историческими метками и пять
групповых фолдов. Внешние четыре кадра из Wikimedia не участвовали
в обучении. У лучшего варианта МТЗ‑1221 определена в 26 из 29 случаев,
МТЗ‑82 — в 56 из 60. В этой проверке окончания `82.1` и `1221.7`
сведены к базовым моделям. Перед выкладкой в API нужен отдельный тест
с подтверждёнными моделями и разными физическими машинами. Для семейств
вариант с центральным кропом был стабильнее между val и test. Для МТЗ
вписывание сохранило больше деталей кузова и дало лучший результат.

Для загрязнения сравнили бинарную линейную голову на отдельных
замороженных признаках. У кандидата ConvNeXt в обучении 371 условно чистый
и 94 грязных реальных кадра после отбора по флагам. Порог 0,218 выбран
по прогнозам на отложенных группах внутри обучающего пула с ограничением
на ложные тревоги 10%. В групповой проверке внутри обучающего пула получено
93/94 и 15/371. На контрольных 28 грязных и 17 чистых результат —
28/28 и 2/17, у v3 при её рабочем пороге — 25/28 и 2/17. Эта контрольная
выборка уже использовалась в предыдущей диагностике, а разметка части
пограничных кадров требует пересмотра. Для эксплуатационной приёмки
нужны новые независимые данные, в том числе чистая мокрая техника,
грязь на корпусе, загрязнённая ходовая часть и зимние сцены.

Последовательность воспроизведения из корня репозитория:

```powershell
python -m scripts.build_grouped_family_split --output output/dataset_audit_next
python -m scripts.benchmark_grouped_recognition --split output/dataset_audit_next/family_split.csv --dino-weights weights/dinov2-small.safetensors --output output/dataset_audit_next
python -m scripts.predict_recognition_candidate --head output/dataset_audit_next/state_candidate.json path/to/photo.jpg
python -m scripts.predict_recognition_candidate --head output/dataset_audit_next/mtz_candidate.json --dino-weights weights/dinov2-small.safetensors path/to/mtz.jpg
```

Для эксперимента без DINOv2 опустите `--dino-weights`. Веса DINOv2
использованы из [карточки timm](https://huggingface.co/timm/vit_small_patch14_dinov2.lvd142m).
Включённый в репозиторий итог содержит счётчики и метрики. Исходные
снимки, пофайловые прогнозы и веса хранятся локально.

При следующем сборе фидбэка применяйте `--require-user-state`.
CLI сверяет точные совпадения с текущими реальными контрольными
наборами. Новые контрольные деревья можно указать через
`--held-out-dir`. Группировку близких дублей повторяют перед
формированием новой версии датасета.
