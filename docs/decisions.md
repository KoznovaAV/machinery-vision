# Технические решения

Формат: решение — причина — где зафиксировано. Даты — по истории исходного
репозитория, где они известны.

## Модель и обучение

1. **Одна сеть, две головы** (`model_head` 768→4, `state_head` 768→2) над общим
   эмбеддингом ConvNeXt-Tiny: backbone считается один раз.
   `docs/ARCHITECTURE.md`.
2. **Partial fine-tuning, одна размороженная стадия** (`num_unfrozen_stages=1`):
   на датасете умеренного размера меньший риск переобучения, чем при двух стадиях.
   Backbone учится в 10 раз медленнее голов (базовый LR `5e-4`). `docs/RETRAIN.md`.
3. **Uncertainty weighting** (Kendall et al., 2018) для баланса потерь задач;
   стабильнее gradnorm. `docs/RETRAIN.md`, `reports/MODEL_CARD.md`.
4. **Единый `image_size = 384`** для train, eval и инференса — только из
   `configs/config.yaml`.
5. **Дообучение с тёплого старта** (`--init-checkpoint`, `--lr 1e-4`,
   `--early-stopping-patience 3`) вместо полного прогона; полный прогон — только
   при смене архитектуры или катастрофическом расхождении данных.
6. **Новые чекпоинты кандидатов — в отдельную папку** (`--weights-dir weights/ft_…`),
   чтобы не затереть лучший по семье.
7. **Выбор рантайм-чекпоинта:** сначала `config.weights.multi_task`, иначе самый
   свежий по времени изменения среди `weights/multi-task-best-*.ckpt`. Сортировка
   по имени не используется: строка `"19"` больше `"13"` и выбирала бы не ту эпоху.
   `src/models/loader.py`.

## Классы

8. **4 семьи без подмоделей.** `mtz_82` и `mtz_1221` слиты в `mtz_belarus`
   (2026-08-29); имена-псевдонимы сводятся через `CLASS_ALIASES`.
9. **Порядок классов фиксирован** и является контрактом с весами головы; новый
   класс добавляется только в конец, число классов в конфиге обновляется вместе с
   `MODEL_CLASSES`.
10. **Классы и размеры не хардкодятся**: источник правды —
    `src/config/classes.py` и `configs/config.yaml`.

## Состояние clean / dirty

11. **Решение по порогу, а не по argmax:** `p(dirty) >= api.state_dirty_threshold`.
    Порог — максимальный, при котором dirty recall на `data/real_dirty_val` держится
    у цели 0.90; подбирается `scripts/error_analysis_state.py --sweep`. Рабочее
    значение 0.60 (2026-08-31).
12. **Синтетическая грязь + реальная.** Голова состояния, обученная только на
    синтетике, проседала на реальной корке ила (dirty recall 0.375 → 0.906 после
    добавления реальных фото и деградации `mud_crust`, 2026-08-30). Реальные фото —
    с префиксом `real_`.
13. **Нейтральные аугментации (снег, «мыло» камеры, блики) применяются и к `clean`,
    и к `dirty`** (2026-09-02), чтобы голова не училась «снег / мыло / блик = dirty».
    Грязь смещена в нижнюю зону кадра, порог видимости синтетической грязи
    `MIN_DIRT_INTENSITY=0.18`.
14. **Снежные фото удалены** из всех наборов; поведение на зимней технике не определено.

## Данные

15. **Стратифицированное разбиение 70 / 15 / 15** по `(класс, состояние)`,
    фиксируется `--seed`; дедупликация по MD5 между источниками.
16. **Held-out реальной грязи — 20 %** (`data/real_dirty_val`) плюс отложенный
    резерв `data/real_dirty_reserve`, вводимый в оценку осознанно, чтобы всегда
    оставался ни разу не виденный моделью набор.
17. **Сплит `test` не используется для подбора гиперпараметров**; прогон — один
    раз перед выкладкой.
18. **Сбор: DuckDuckGo + perceptual-hash дедупликация + CLIP zero-shot фильтр**;
    при низкой уверенности — `to_review/` и ручной разбор.

## API и эксплуатация

19. **`/feedback` только складывает данные** и не меняет модель или датасет;
    вливание — офлайн через `scripts/ingest_feedback.py` (по умолчанию `--dry-run`,
    фото и манифест копируются, а не перемещаются). Ориентир для переобучения — 50
    новых примеров.
20. **`needs_review` при `confidence < 0.6`** (`api.confidence_threshold`).
21. **Ключи API — только в переменной окружения** `TRACTOR_VISION_API_KEYS`, не в
    конфиге; при `auth_enabled: true` и пустой переменной сервис не стартует.
    Rate limit — на ключ при включённой аутентификации, иначе на IP.
22. **Реестр моделей из конфига** (`config.models`): имя записи — параметр
    `?model=`, дефолт `machine`; незагрузившаяся запись не блокирует остальные.
23. **Docker: CPU-образ по умолчанию**, GPU — через `--build-arg TORCH_VARIANT=cu121`;
    веса и данные внутрь образа не зашиваются, монтируются томами. CMD по умолчанию — API.
