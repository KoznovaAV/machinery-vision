# Правила разметки

Свод правил, которые уже заложены в данные, скрипты и документацию проекта.
Источники: `src/config/classes.py`, `docs/DATA.md`, `reports/MODEL_CARD.md`,
`scripts/collect_tractors.py`, `scripts/pseudo_label_dirty.py`,
`scripts/split_real_dirty.py`.

## Семья трактора

Метка — **семейство техники целиком**, без деления на подмодели.

| Класс | Что входит |
|-------|------------|
| `chtz` | ЧТЗ (Уралтрак): Б10М, Т-170, Т-130 |
| `johndeere` | John Deere: 6R, 7R, 8R |
| `kirovets` | Кировец: К-744, К-7М, К-525 |
| `mtz_belarus` | МТЗ / Belarus: 82, 1221, 1523, 2022 |

- Имена и порядок классов задаёт `MODEL_CLASSES` в `src/config/classes.py`.
  Порядок — контракт с весами головы; новый класс добавляется только в конец.
- Псевдонимы `mtz_82` и `mtz_1221` сводятся к `mtz_belarus` (`CLASS_ALIASES`)
  при разметке и сборе данных.
- Служебные папки (`to_review` и подобные) при подготовке датасета не считаются
  классами: классы берутся явно из `MODEL_CLASSES`.

## Состояние

Два класса: `clean` (индекс 0) и `dirty` (индекс 1).

- Граница между ними размыта: состояние бинарное и субъективное, лёгкая пыль
  может быть размечена и распознана как `clean`.
- Синтетическая грязь (`*_dirty0`, `*_dirty1`) кладётся в `dirty/`, оригиналы —
  в `clean/`. Деградации накладываются на технику, небо остаётся чистым.
- Реальные грязные фото в обучающей выборке — с префиксом `real_`; пользовательский
  фидбэк — с префиксом `feedback_`. Префикс позволяет считать и удалять источники
  отдельно.
- Состояние из фидбэка берётся из `user_state` манифеста, если оно задано и
  валидно, иначе предсказывается моделью.

## Что не попадает в датасет

- Фото без трактора: при сборе отсекаются CLIP zero-shot (позитивные промпты —
  трактор, сельхозтехника, бульдозер; негативные — автомобиль, грузовик, человек,
  пейзаж без техники, схема/рисунок, интерьер).
- Дубликаты: perceptual hash при сборе (точные и почти-дубликаты) и MD5 содержимого
  при объединении источников, чтобы одно фото не попало одновременно в `train`
  и `test`.
- Битые и обрезанные изображения: проверяются `scripts/check_images.py`.
- Снег на технике и в кадре: снежные фото удалены из всех наборов (`train`, `val`,
  `processed`, probe), поведение на зимних кадрах не определено.
- Мусорные кадры реальной грязи — удалены при чистке наборов.

## Ручные шаги

Единственный обязательный ручной шаг — разбор `to_review/`: фото, для которых
уверенность CLIP (при сборе) или классификатора (при псевдоразметке, порог по
умолчанию 0.8) ниже порога, раскладываются по классам вручную, мусор удаляется.
`to_review/` должен быть вычищен до запуска `prepare_dataset`.

## Held-out наборы

- `data/real_dirty_val` — 20 % размеченных реальных грязных фото, не участвуют в
  обучении; на них измеряется dirty recall.
- `data/real_clean_probe` — реальные чистые фото для оценки false-dirty. Перед
  добавлением проверяйте совпадения с обучающими фото. Кадры кладутся
  вручную, в git только заглушка `.gitkeep`.
- `data/real_dirty_reserve` — резерв реальной грязи, вводится в оценку отдельным
  решением, а не автоматически.
- Сплит `test` в `data/dirty_clean` — финальный held-out, прогоняется один раз
  перед выкладкой и не используется для подбора гиперпараметров.

## Проверка разметки глазами

Грязь на технике, а не на небе; `to_review/` вычищен; матрица ошибок 4×4;
каждый класс представлен во всех трёх сплитах.

## Не определено в репозитории

Количественного критерия «грязный / чистый» (доля покрытия, баллы и т. п.) и
инструкции для разметчиков по пограничным случаям в проекте нет — граница
задана только примерами в данных.
